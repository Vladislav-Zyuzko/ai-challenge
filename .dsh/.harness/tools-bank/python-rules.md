# Правила инструмента: python (статический сервер разработки)

harness_version: 0.1
Версия правил: 0.1
Статус: active
Проверено: 2026-09-20, Windows, Python 3.12.10

## 1. Назначение

**Уместен** ровно для одного: отдать папку продукта по HTTP на `localhost`, чтобы
открыть браузерную страницу и пройти ручной чек-лист. Одна команда, стандартная
библиотека, ноль установок.

**Не уместен** как продуктовая серверная часть и как «настоящий» сервер: нет TLS,
аутентификации, кэш-заголовков, продакшн-поведения. Продукт по контракту не имеет
серверной логики — этот сервер только раздаёт статику во время разработки и проверки.

## 2. Предусловия среды

| Предусловие | Как проверить (health-check) | Проверенный факт |
|---|---|---|
| Python 3.x установлен | `python --version` (или `py --version`) | `Python 3.12.10` |
| Доступен модуль `http.server` | `python -c "import http.server; print('http.server ok')"` | `http.server ok` |
| Свободный TCP-порт на loopback | запуск сервера и GET-запрос | порт `8765`/`8766` свободны, GET → `200` |
| Корректный MIME для статики | GET `.js` и посмотреть `Content-Type` | `.js` → `application/javascript`, `.html` → `text/html` |

## 3. Как ставить задачу исполнителю

Исполнителю не нужно «писать» сервер — нужно поднять и проверить:

- **вход:** путь к папке продукта (там, где лежит `index.html`), порт;
- **команда:** из папки продукта `python -m http.server <порт> --bind 127.0.0.1`;
- **ожидаемый результат:** GET на `http://127.0.0.1:<порт>/index.html` возвращает `200`,
  статика отдаётся с верным MIME; страница открывается в браузере;
- **границы:** только loopback-адрес; никаких данных и логики продукта на сервере;
  после проверки процесс сервера завершается;
- **отчёт исполнителя:** команда, порт, код ответа, что проверено в браузере.

## 4. Как проверять результат

Воспроизводимо (проверено 2026-09-20):

```powershell
$p = Start-Process python -ArgumentList '-m','http.server','8765','--bind','127.0.0.1' -WorkingDirectory <папка-продукта> -PassThru -WindowStyle Hidden
Start-Sleep -Seconds 2
Invoke-WebRequest -Uri 'http://127.0.0.1:8765/index.html' -UseBasicParsing   # ожидаем 200
Stop-Process -Id $p.Id -Force
```

Признак успеха: `200` на `index.html` и `application/javascript` на модулях.
Дальше — ручной чек-лист в браузере (см. `web-rules.md`, раздел 5).

## 5. Лучшие практики и грабли

- Всегда `--bind 127.0.0.1`: продукт локальный, наружу порт не выставляется
  (это же требование инварианта «только localhost»).
- Запускать **из папки продукта** — иначе `http.server` отдаёт не тот корень,
  и модули не находятся (`404`).
- Занятый порт → взять следующий; сервер печатает об ошибке привязки, проверять вывод.
- Сервер держит окно процесса: в фоне запускать `Start-Process -WindowStyle Hidden`,
  завершать `Stop-Process -Id <pid> -Force`, иначе порт остаётся занят.
- Первый запуск может вызвать запрос Windows Firewall на сетевой доступ — при
  `--bind 127.0.0.1` он не нужен, запрос можно отклонить.
- Кэш не управляется: при «залипшей» старой версии страницы жать `Ctrl+F5`.
- Не использовать `python -m http.server` как способ запустить продукт у пользователя
  в проде: это dev-инструмент, он назван так в `usage.md`.

## 6. Ограничения

- Только статика: никакого выполнения логики продукта на сервере.
- Нет TLS/HTTPS, аутентификации, сжатия и кэш-заголовков.
- Не продакшн-сервер; в интернет не публикуется.
- Не заменяет автотесты логики — только ручную проверку интерфейса в браузере.
