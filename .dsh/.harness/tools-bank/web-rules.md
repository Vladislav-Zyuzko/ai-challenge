# Правила инструмента: web — vanilla HTML + CSS + JS (без сборки)

harness_version: 0.1
Версия правил: 0.2
Статус: active
Проверено: 2026-09-20, Windows, браузеры Edge/Chrome, Node 24.17.0, Python 3.12.10
Ревизия 002 (2026-09-20): структурные проверки разметки автоматизированы через `node:fs`
(см. `node-rules.md`), ручной остаётся только интерактив.

## 1. Назначение

**Уместен** для небольших браузерных инструментов, которые должны запускаться локально
без установки, сборки и сети: одна страница, немного состояния, логика помещается в
один-два модуля. Типовые задачи: калькулятор, конвертер, просмотрщик, локальная форма.

**Не уместен**, когда нужен роутинг и много экранов, компонентная библиотека,
управление состоянием, SSR, авторизация, работа с API, офлайн-хранилище, типизация
и сборка, тесты DOM без установки драйвера. Для такого берётся инструмент со сборкой
(Vite/React) или другой стек — это решение уровня продукта, а не «допиливание» vanilla.

Ключевое свойство: **ноль зависимостей и ноль шага сборки**. Всё, что требует
`npm install`, `node_modules`, бандлера или CDN, этому инструменту запрещено —
иначе рушится инвариант «офлайн, без сборки».

## 2. Предусловия среды

| Предусловие | Как проверить (health-check) | Проверенный факт |
|---|---|---|
| Браузер с ES-модулями и DOM | `Test-Path 'C:\Program Files\Google\Chrome\Application\chrome.exe'` | `True` (также Edge: `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`) |
| Страница отдаётся по HTTP (не `file://`) | нужен статический сервер — см. `python-rules.md` | `python-rules.md` active, GET → 200 |
| Модули с расширением `.js` отдаются как JS | заголовок `Content-Type` в ответе сервера | Python `http.server` отдаёт `application/javascript` для `.js` — валидный JS MIME, браузер грузит модуль |
| Node для прогона логических тестов | `node --version` | `v24.17.0` — см. `node-rules.md` |

`file://` для этого инструмента **не работает**: браузер блокирует загрузку ES-модулей
с локального диска. Это предусловие способа запуска, а не продуктовое требование.

## 3. Каноническая структура проекта

Тело проекта (шаг E скилла `create-project`) для этого инструмента не генерируется
командой — генератора нет. Структура фиксируется здесь и создаётся как обычные файлы:

```
<project>/
  index.html                 # точка входа: разметка + подключение стилей и модуля
  styles.css                 # оформление; без препроцессоров и CSS-фреймворков
  src/
    calculator.js            # ЧИСТАЯ логика: экспорты, ни одного обращения к DOM
    app.js                   # тонкая связка: DOM ↔ логика, без бизнес-правил
  tests/
    calculator.test.mjs      # node:test, импортирует ../src/calculator.js
```

Контракты файлов (нарушение = нарушение правил инструмента):

- `src/calculator.js` — только чистые функции и константы; **не** импортирует DOM,
  не обращается к `document`/`window`, не делает сетевых вызовов. Импортируется и
  браузером, и Node-тестами.
- `src/app.js` — единственное место, где есть DOM: читает ввод, вызывает логику,
  пишет результат. Бизнес-правил (округление, деление на ноль) здесь нет.
- `index.html` — подключает `styles.css` и `<script type="module" src="./src/app.js"></script>`;
  `package.json` не нужен (Node 22.7+ определяет ESM в `.js` по синтаксису — проверено
  на 24.17.0 без предупреждений).
- `tests/*.test.mjs` — тесты логики; имя файла `*.test.mjs`, чтобы `node --test` его находил.

## 4. Как ставить задачу исполнителю

Задача приходит одним пакетом (правила инструмента — системный промпт исполнителя):

- **вход:** одна атомарная задача, список файлов во владении (`files_owned`),
  рецепт в одну-две строки, команда проверки, ссылки на инварианты;
- **ожидаемый результат:** названные файлы созданы/изменены; проверка проходит;
  никакие файлы вне `files_owned` не тронуты;
- **границы:** никаких новых зависимостей, сборщиков, CDN, фреймворков; никаких
  файлов вне структуры выше; DOM-код только в `app.js`, логика только в `calculator.js`;
- **отчёт исполнителя:** что сделано, где лежит, вывод проверки, что осталось незакрытым.

## 5. Как проверять результат

Дешёвые проверки в порядке возрастания цены:

1. **Логика (обязательно):** `node --test-isolation=none --test "tests/*.test.mjs"`
   из папки продукта — выход `0`, счётчики `pass`/`fail`. Один файл можно прогнать
   как `node tests/calculator.test.mjs`.
2. **Целостность и структура файлов (автоматизируется):** все файлы структуры существуют;
   `src/calculator.js` не содержит `document`/`window`; в разметке есть нужные контейнеры и
   ровно ожидаемый набор `data-key`; нет внешних `src`/`href`/`@import`/`url(http`.
   Дешевле и надёжнее оформить это тестом на `node:fs` (см. `node-rules.md`) — файлы
   читаются напрямую, DOM не нужен.
3. **Отсутствие сети (I1):** поиск `fetch|XMLHttpRequest|WebSocket|import(` по `*.js|*.html`
   → пусто; в браузере DevTools → Network нет запросов вне `localhost`.
4. **Ручной чек-лист в браузере:** сервер из `python-rules.md`, открыть страницу,
   пройти сценарий (операции, ошибка деления на ноль, `C`), сверить состав кнопок.
5. **Отсутствие сборки:** в проекте нет `package.json`, `node_modules`, конфигов
   бандлера, `<script src>` с внешних адресов.

Автоматического теста **интерактива** нет: драйвер браузера требует установки — это вне
правил инструмента (см. ограничения). Структура разметки и состав `data-key` проверяются
автоматически (тест на `node:fs`), поведение логики — юнит-тестами, живой ввод в браузере —
headless-браузером (CDP без установок) или ручным чек-листом.

## 6. Лучшие практики и грабли

- `<script type="module">` уже отложенный (`defer` по умолчанию) — порядок инициализации
  не зависит от места тега, но модуль обязан найти свои элементы к моменту работы.
- Слушатели вешаются **один раз** на контейнер клавиатуры, разбор кнопки — по
  `data-*` атрибуту (делегирование). По слушателю на кнопку — лишний код и лишние ошибки.
- В DOM пишется только `textContent`; `innerHTML` для значений из ввода запрещён.
- Округление результата — одна функция (например через `Number(v.toPrecision(12))`)
  в логике, а не разбросанное `toFixed` по интерфейсу; `toFixed` режет точность
  и добавляет хвостовые нули.
- Деление на ноль обрабатывается **до** деления и возвращается как результат-ошибка
  (`{ ok: false, error: '…' }`), а не бросается исключением: интерфейс рисует сообщение,
  логика остаётся чистой и тестируемой.
- Состояние калькулятора (текущий ввод, операнд, операция, ожидание) живёт в одном
  месте (`app.js`), логика получает значения аргументами и ничего не помнит.
- Грабли браузера: `file://` + модули = CORS-ошибка; жёсткий кэш статики — при
  странном поведении проверить с `Ctrl+F5`; разные локали разделителя — не использовать
  `Intl` и не полагаться на локаль.
- Грабли Node: ESM-импорт требует явного расширения (`./calculator.js`, не `./calculator`);
  в sandbox-окружении `node --test` с изоляцией процессов падает `spawn EPERM` —
  использовать `--test-isolation=none` (см. `node-rules.md`).

## 7. Ограничения

- Нет автоматической проверки **рендеринга и кликов** без браузерного драйвера: структура
  разметки и состав `data-key` проверяются статически, интерактив — headless-браузером
  через CDP (без установок) или руками по чек-листу. Это осознанная граница, а не недоделка.
- Нет сборки, минификации, tree-shaking, типов и линтера из коробки: ошибки в
  `app.js` видны только при запуске страницы.
- Нет `import` npm-пакетов и CDN — только локальные файлы.
- Статика без кэш-заголовков; сервер разработческий (см. `python-rules.md`).
- Инструмент не масштабируется на многоэкранные приложения: при росте продукта
  это повод к смене стека решением пользователя, а не «наращивание» vanilla.

## 8. Версия и статус

- Версия правил: **0.2**, статус **active**, `harness_version: 0.1`.
- Область действия: локальные браузерные инструменты без сборки и зависимостей.
- Ревизии: 0.1 — первичные правила; 0.2 — статические проверки разметки автоматизированы

  или при изменении структуры проекта — новая версия правил.
