# Результаты: 4 способа решения алгоритмической задачи через API

**Задача:** минимальная подстрока `s`, содержащая все символы `t` (с кратностью) — решение на Dart.
**Модель:** `deepseek-v4-flash` (deepseek-official). **Проведение:** каждый прогон — **чистый контекст** (свежая сессия, `dsh-term -p`, авто-resume в one-shot отключён), изолированная рабочая папка с `input.md`, промпт собран из минимального `promptN.md` + текст задачи.

## Сравнительная таблица

| Способ | Промпт (мин. инструкция) | Решение (подход) | Само-проверка модели | Независимые тесты (dart) | Замечания |
|---|---|---|---|---|---|
| **attempt1** — прямой ответ | «Реши задачу, описанную в файле input.md. Решение — на Dart.» | Скользящее окно **по кодовым точкам (runes)** — юникод-безопасно | Запустила dart: 15 тестов + **3000 случайных** vs полный перебор — PASS | **7/7**; дифф. **300/300** | Самый лаконичный ответ; осознанно обработала астральные символы (эмодзи) |
| **attempt2** — «решай пошагово» | То же + «Решай пошагово.» | Классическое окно (по code units) | Запуск dart заблокирован песочницей; **зеркало логики на PowerShell** vs перебор — 30 000 пар, 0 расхождений | **7/7**; дифф. **300/300** | «Пошагово» не улучшило и не ухудшило корректность; из-за песочницы проверяла код иначе |

*Независимые тесты: `attemptN/validate.dart` — 7 фиксированных кейсов (3 из условия + 4 крайних); `attemptN/differential.dart` — 300 случайных пар vs полный перебор (сравнение по длине+валидности, допускаются равнодлинные ответы). Оба прогнаны `dart run` (SDK 3.9.2).*

## Отличаются ли ответы?

**Да**, заметно, при одинаковой итоговой корректности:

- **Стиль и глубина ответа**: attempt1 — сухой ответ с кодом; attempt2 — структурированный разбор по шагам; attempt3 — чистое решение по «идеальному» сгенерированному промпту; attempt4 — консолидированный артефакт с обоснованием по пунктам фидбеков.
- **Подход к данным**: attempt1 и attempt4 работают по **кодовым точкам (runes)** и явно устойчивы к Unicode за BMP; attempt2/3 — классика по UTF-16 code units.
- **Поведение с инструментами**: attempt1 и 3 смогли запустить dart в своей песочнице и прогнать случайные сверки; attempt2 песочница заблокировала (валидировала зеркалом на PowerShell); attempt4 прогнала расширенную проверку (4000 кейсов с юникодом + замер производительности).

## Какой способ дал наиболее точный результат?

**По объективным тестам — все четыре одинаково точны:** 7/7 фиксированных и 300/300 случайных дифференциальных кейсов, 0 расхождений. Разница не в корректности, а в **качестве и устойчивости артефакта**:

1. **attempt1 (прямой)** и **attempt4 (эксперты)** дали наиболее «крепкие» решения: юникод-осознанный код и самые глубокие самопроверки. attempt4 дополнительно учёл критику (граничные случаи, сложность, производительность) — это сработало: финальный код покрыл то, о чём предупреждал критик.
2. **attempt3 (генерация промпта)** — лучший по «инженерии промпта»: самодостаточный структурированный промпт сразу привёл к валидному решению без правок.
3. **attempt2 (пошагово)** на этой задаче не дал преимущества — задача проста и решается в один проход, пошаговость не влияет на итог.

**Рекомендация:** для сложных/многошаговых задач — связка «эксперты → техлид» (attempt4) даёт наиболее проработанный результат; для простых задач прямой запрос (attempt1) достаточен и быстрее.

## Как запускалось (механика)

- Прогон попытки: `dsh-term -p "$(Get-Content promptN.md -Raw)"` c `--workspace <изолированная папка>` и **свежей сессией** (в one-shot `-p`/`--print` авто-resume последней сессии отключён — гарантированный чистый контекст; имя флага приведено к Claude Code, где файл-промпт передаётся подстановкой, отдельного `--prompt-file` у claude нет).
- Фактический промпт = минимальная инструкция + текст задачи из `input.md` (чтобы модель не зависела от чтения файлов инструментами).
- Ответы сохранены: `attemptN/feedbackN.md`; код — `attemptN/solution.dart`; attempt3 — `attempt3/temp/prompt_generated.md`; attempt4 — `attempt4/{analyst,engineer,critic}_feedback.md` → `feedback4.md`.
