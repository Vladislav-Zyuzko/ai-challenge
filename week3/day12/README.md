# day12 — персонализация: три профиля на одном наборе вопросов

Сценарий проверяет главное требование задания: **профиль подключён к каждому запросу**
(он часть system prompt), поэтому один и тот же вопрос даёт разные ответы, а стиль/формат/
ограничения применяются без упоминания их в вопросе.

```
profiles/      три профиля в формате dsh-term (~/.dsh-term/user-profiles/<slug>.md)
questions.md   набор вопросов и что в них проверяется
run.ps1        прогон: 4 плеча × 3 вопроса, по процессу на ответ (one-shot)
analyze.mjs    разбор runs/*.txt: длина, доля кода, out-токены, сработали ли правила
run-learn.ps1  проверка автообучения: профиль → одно сообщение → /exit, дифф профиля
runs/          результаты (stdout = ответ, stderr = диагностика dsh-term)
```

## Запуск

```powershell
powershell -ExecutionPolicy Bypass -File week3/day12/run.ps1          # все плечи
powershell -ExecutionPolicy Bypass -File week3/day12/run.ps1 -Only tolko-kod
powershell -ExecutionPolicy Bypass -File week3/day12/run-learn.ps1    # автообучение профиля
node week3/day12/analyze.mjs --md
```

`run.ps1` копирует `profiles/*.md` в `<DshHome>\user-profiles` и запускает по одному
процессу на (плечо, вопрос): `dsh-term -p "<вопрос>" --user-profile <slug>`.

**Почему one-shot, а не REPL.** В интерактивной сессии профиль дообучается по ходу
(это штатное поведение), и плечи стали бы несравнимыми — у каждого свой набор пунктов.
One-shot профиль не меняет вообще, поэтому все плечи получают ровно тот профиль, что
лежит в `profiles/`. Это же свойство делает прогон воспроизводимым.

## Плечи

| Плечо | Профиль | Ожидаемый ответ |
|---|---|---|
| `none` | не подключён | точка отсчёта: как модель отвечает «из коробки» |
| `kratko` | `Кратко и по делу` | вывод сразу, ≤5 строк, без резюме и списков |
| `podrobno` | `Подробно с объяснением` | разбор по пунктам, причины решений, раздел «Итого» |
| `tolko-kod` | `Только код` | один блок кода, без пояснений, заголовков и списков |

Плечо `none` — не «пустой профиль», а именно отсутствие персонализации: сравнивая с ним,
видно вклад профиля, а не разброс модели.

## Что ещё лежит в `runs/`

Кроме ответов по плечам (`<вариант>-q<N>.txt`) там логи двух проверок поведения:

| Файл | Что показывает |
|---|---|
| `auto-learn-before.md`, `auto-learn-after.md`, `auto-learn-console.txt` | автообучение: профиль из одного пункта вырос до трёх после одного сообщения |
| `hot-update-console.txt` | обновлённый профиль подхватывается между ходами: `+1 пункт` → `перезапуск рантайма` → следующий запрос |
| `profile-compact-console.txt` | профиль на 878 токенов перерос бюджет и был сжат (`~566`) с явным сообщением |
