# support-mcp — локальный сервер поддержки (день 33)

MCP-сервер вокруг обращений пользователей. Это «CRM» из задания в самом дешёвом виде:
данные — два JSON-файла в `data/`, доступ — стандартными инструментами MCP. Замена файлов на
настоящую CRM сводится к замене `store.py`, промпт и скилл при этом не меняются.

## Данные

```
data/users.json     пользователи: id, имя, почта, тариф, ОС, версия dsh-term, заметки
data/tickets.json   обращения: id, пользователь, тема, компонент, статус, теги, переписка
```

Обращения связаны с пользователями по `ticket.user → user.id`. Каталог переопределяется
флагом `--data` или переменной `DSH_TERM_SUPPORT_DATA`.

## Инструменты

| Инструмент | Аргументы | Что отдаёт |
|---|---|---|
| `support_list_tickets` | `status` (опционально) | список обращений: номер, тема, пользователь, статус, число сообщений |
| `support_get_ticket` | `ticket_id` | карточка обращения: тема, теги, компонент, пользователь и вся переписка |
| `support_get_user` | `key` | пользователь по id, почте или имени |
| `support_find_tickets` | `query` | поиск по теме, тегам, компоненту и тексту переписки |
| `support_add_comment` | `ticket_id`, `text` | комментарий в обращение — **только с `--readwrite`** |

Ответы — текст: агент читает их как есть, без разбора JSON. Ошибки (нет обращения, нет
пользователя, пустой запрос) возвращаются текстом с подсказкой, а не исключением — иначе
модель увидит падение инструмента вместо причины и не сможет сообщить её пользователю.

## Запуск

```powershell
# диагностика данных без MCP
cd support-mcp
python -m support_mcp.server --check       # {"tickets": 6, "open": 5, "readonly": true}

# как MCP-сервер (stdio) — обычно его поднимает dsh-term
python -m support_mcp.server
python -m support_mcp.server --data C:\путь\к\data --readwrite
```

В `dsh-term` сервер подключён пресетом `--mcp support` и автоматически включается в режиме
`/support`. Проверка соединения и списка инструментов:

```powershell
node dsh-term/dsh-term.mjs --mcp-check support
```

## Тесты

```powershell
cd support-mcp
python tests\test_support.py     # 15 проверок: хранилище, форматы, реестр инструментов
```

Тесты проверяют в том числе, что запись в тикет запрещена без `--readwrite` и что запись
реально попадает в файл, когда разрешена (на копии данных во временном каталоге).
