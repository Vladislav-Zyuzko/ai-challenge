# Процедурный харнесс (`.dsh/.harness/`)

Правила **как вообще работать**: роли агентов, этапы, критерии, дисциплина артефактов.
Харнесс не зависит от конкретного продукта и переносится между проектами без изменений:
всё, что относится к продукту, живёт в узлах продукта (`.project-harness/` и `<слаг>-node/`).

Аналогия: харнесс — это «как строить», харнесс продукта — «что строим».

## Структура

```
.dsh/.harness/
  README.md                     # этот файл: что это и как пользоваться
  agents/                       # роли: что делает каждая, с каким контекстом, чего не делает
    project-architect.md        #   владелец корневого узла, связь с пользователем
    node-architect.md           #   владелец узла: срез, план, оркестрация, сдача
    critic.md                   #   проверка плана: рубрика, severity, формат возражений
    tester.md                   #   верификация: два класса проверок, доказательства
  product-rules/                # правила самого харнесса
    project.md                  #   как из запроса получается инструмент: цикл, инварианты H1–H7
    node.md                     #   структура узла, срез, атомарность, бюджет, отчёты
    state-machine.md            #   этапы, переходы, отказы, контекст ролей
    glossary.md                 #   определения понятий
  tools-bank/                   # правила использования внешних инструментов (заготовка)
    README.md                   #   формат описания инструмента; исполнители появятся здесь
```

## Как этим пользуются агенты

1. Роль читает **свой** файл в `agents/` — там её зона ответственности, входы, выходы
   и границы.
2. Процедуру берёт из `product-rules/`: цикл (`project.md`), правила узла (`node.md`),
   этапы и переходы (`state-machine.md`).
3. Термины сверяет по `glossary.md`, чтобы не расходиться в понятиях.
4. Правила конкретного инструмента (flutter, react, …) — из `tools-bank/`.

Что читает каждая роль на каждом этапе — таблица «Контекст ролей» в
`product-rules/state-machine.md`. Принцип: агент получает **срез**, а не всё подряд.

## Что сюда не попадает

- продуктовые правила конкретного проекта (это `product-rules.md` узла);
- карта инструментов конкретного проекта (это `tools-rules.md` узла);
- планы, отчёты, контракты продукта (это `node-reports/` и файлы узла);
- знания о конкретной среде (пути, версии, особенности репозитория) — только как
  примеры в тексте правил, без привязки к проекту.

## Версия и изменения

- Текущая версия правил: **0.1** (черновик, до первого прогона на реальном узле).
- Узлы фиксируют `harness_version`, по которой строились (см. `product-rules/node.md`).
- Изменение правил процесса — это новая версия харнесса: узлы с расхождением версий
  помечаются как «требует перепроверки» (change propagation).
