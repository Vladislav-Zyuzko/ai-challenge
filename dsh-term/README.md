# dsh-term

Своя интерактивная терминальная CLI для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) — тонкий клиент поверх SDK JSON-RPC протокола. Ноль внешних зависимостей, только Node.js.

## Как это работает

```
dsh-term
   │  spawn
   ▼
dsh --profile sdk   ◄── JSON-RPC 2.0 по newline-delimited stdio
   │  (initialize / session/prompt / shutdown)
   ▼
Harness runtime (полный агент: инструменты, сессии, субагенты)
```

- **Пока модель думает — в терминале переливается синим подпись «Deep diving…»** (градиент бежит по тексту); пошёл видимый ответ — анимация останавливается и текст стримится; после вызова инструмента подпись возвращается.
- **Живой счётчик токенов**: пока крутится «Deep diving…», рядом в скобках (светлее) растёт счётчик выходных токенов — `Deep diving… (237 tokens)`; когда пошёл видимый текст — счётчик тикает хвостиком за строкой ответа. Это оценка по символам стрима (калибруется по фактическому usage), шаги целые: 200…201, от 1000 — 1.1k, 1.2k. Точные цифры — в сводке после хода.
- **Метрики токенов (англ.)**: после ответа — пустая строка, линия на всю ширину терминала и блок, начинающийся с `turn`:

  ```
  (ответ модели)

  ────────────────────────────────────────────
  — turn 2 ended: completed
    tokens: in 16.2k (cache 7.9k) / out 5
    requests: 2 (this turn: 1)
    context: 8.1k / 1M (0.809%)
  ```

  Где: `in` — суммарные входные токены сессии (включая кэш-токены), `(cache …)` — сколько из них пришло из кэша (тарифицируется в разы дешевле), `out` — выходные токены (включая thinking), `requests` — сколько раз сходили в модель (в агентном ходе на один вопрос их бывает много: каждый вызов инструмента — новый запрос, и каждый заново отправляет всю историю), `context` — размер последнего запроса, то есть текущее заполнение окна.

  В многошаговых ходах (цепочка инструментов) стоимость каждого шага выводится сразу (`· step 2: in … / out …`). Потолок окна — 1M (как у адаптера DeepSeek v4; переопределить: `DSH_TERM_CTX_MAX`). В one-shot метрики идут в stderr, stdout остаётся чистым.
- **Markdown-рендер (лёгкий)**: в интерактивном TTY ответ подсвечивается — заголовки жирным синим DeepSeek, `**жирный**`, `*курсив*`, `` `код` `` голубым, кодовые блоки (```/~~~) приглушённым. Рендер ничего не добавляет и не удаляет (текст и копия не меняются), работает по чанкам: незакрытые к концу фрагмента конструкции остаются как есть, состояние кодовых блоков держится весь ход. В one-shot (`-p`) вывод остаётся raw markdown.
- **Промпт** `dsh> ` — слово «dsh» выделено жирным фирменным синим DeepSeek (#4D6BFE) для контраста (без цвета на пайпе / `NO_COLOR`).
- Активность инструментов выводится строками (`▶ bash …`, `✔ done`)
- Сессии стойкие: последняя сессия запоминается и **автоматически продолжается** при следующем запуске; есть `/resume` и `--resume`
- События субагентов (`subagent.started`) тоже рендерятся

## Первый вход: токен

При первом запуске `dsh-term` сам запросит DEEPSEEK API ключ (ввод скрыт) и сохранит его в managed-хранилище харнесса — `<home>/.credentials.yaml` (формат `version: 1` / `refs` / `records`). Дальше токен берётся оттуда автоматически; харнесс подхватывает его сам. Сменить токен — команда `/token`.

Приоритет токена: окружение (`DEEPSEEK_API_KEY`) → хранилище → интерактивный запрос.

## Запуск

```powershell
dsh-term                       # интерактивный REPL
dsh-term -p "вопрос"           # one-shot: один ответ и выход
```

One-shot режим (`-p, --print <text>`) — как `claude -p`: в stdout попадает **только ответ** (диагностика — в stderr), контролы `--format/--max-length/--stop/--max-tokens/--temperature` применяются именно к этому ответу. Выход: 0 при `completed`, 1 при ошибке. Промпт из файла — как в claude, через подстановку:

```powershell
dsh-term -p "$(Get-Content prompt.md -Raw)"
```

В one-shot автоматически добавляется дисциплина «только итоговый результат» (без описания процесса/промежуточных заметок), чтобы при перенаправлении вывода в файл попадал финальный ответ, а не рабочий нарратив агента.

```powershell
dsh-term -p "переведи в json: {…}" --format json --max-length 1000
dsh-term -p "кратко" --stop "END"            # маркер уходит с промптом
```

Изолированный home по умолчанию — `~/.dsh-term` (SDK-рекомендация: не смешивать с `~/.dsh`). Чтобы переиспользовать managed credentials из общего home:

```powershell
dsh-term --dsh-home C:\Users\<you>\.dsh
```

## Опции

| Флаг | Назначение |
|---|---|
| `--dsh-home <path>` | Harness home (default: `~/.dsh-term`) |
| `--profile <name>` | профиль рантайма (default: `sdk`) |
| `--provider <id>` | провайдер (default: `deepseek-official`; env `DSH_TERM_PROVIDER`) |
| `--model <name>` | модель (default: `deepseek-v4-flash`; env `DSH_TERM_MODEL`) |
| `--max-tokens <n>` | жёсткий кап токенов ответа (адаптер) |
| `--temperature <n>` | температура сэмплинга 0..2 (умолчание — провайдерская, 1.0); действует на агента сессии |
| `--format <spec>` | формат ответа: пресет (`json`/`plain`/`markdown`/`bullets`/`code`/`table`) или свободное описание |
| `--max-length <n>` | лимит длины ответа в символах: инструкция модели + обрезка показа с пометкой |
| `--stop <marker>` | стоп-символ: передаётся с промптом; показ обрывается при генерации маркера (сам маркер не печатается) |
| `--session <id>` | продолжить конкретную сессию (синоним: `--resume <id>`) |
| `--workspace <path>` | рабочая папка сессий (default: текущая) |
| `--dsh-bin <path>` | путь к `dsh` (default: `dsh` из PATH) |

### Контролы ответа (`--format` / `--max-length` / `--stop`)

- `--format json` → инструкция «отвечай строго валидным JSON»; любой другой текст → свободное описание формата.
- `--max-length N` → инструкция «не длиннее N символов» + жёсткая обрезка показа: `…[обрезано dsh-term: лимит N символов]`.
- `--stop "END"` → **стоп-символ передаётся с промптом** (модель получает «заверши ответ ровно маркером "END"»), и в момент, когда маркер сгенерирован в потоке, показ обрезается на нём (сам маркер не печатается).
- **Скоуп**: все три контрола действуют на **один следующий ответ**, затем автосброс.
- `--format`/`--max-length` — мягкие (инструкция в промпте); `--max-length`/`--stop` дополнительно обрезают показ на клиенте (жёстко, но сессия хранит полный текст).


## Команды REPL

```
/                список доступных команд
/help [команда]  справка
/session         показать id текущей сессии
/resume [id]     продолжить сессию: по id или выбором из списка
/new             начать новую сессию
/token           сменить сохранённый API ключ
/publish-day     git+gh: коммит → push → PR day→week (по .dsh/SKILLS)
/exit            завершить (или Ctrl+C)
```

### Меню команд (интерактивный режим)

Все команды знать наизусть не нужно: начни вводить **`/`** — под строкой ввода появится меню команд.

- набери **`/`** — меню со **всеми** командами;
- набери **`/`** + подстроку (например `/res`) — только команды, **матчащиеся** с подстрокой (по префиксу или вхождению);
- **↑/↓** — выбор команды в меню;
- **Enter** — запустить выбранную команду (или отправить строку, если меню закрыто);
- **Esc** — закрыть меню (набранный текст остаётся).

Меню отделено от чата горизонтальной линией-разделителем; пока меню открыто, блок
периодически перерисовывается, чтобы «призрачные» копии строк после переключения
вкладок/фокуса терминала не накапливались.

Меню работает только в интерактивном терминале (TTY); при вводе из файла/пайпа команды пишутся целиком, как раньше.

### Заголовки сессий

Сессии в списке показываются не только по id — сначала идёт короткий **заголовок**, а id уходит вторичным (тусклым) текстом, как в Claude:

```
1. «объясни коротко что такое контекстное окно моде…» 2acbe5bd-837c-4620-9670-182abd39fed9
```

- **Источник заголовка** — LLM-саммаризация первого запроса: dsh-term делает отдельный дешёвый вызов API (≤10 слов, `thinking` отключён, ~85 токенов) и ставит суть запроса. Пример: «Привет! Помоги выбрать авиабилеты, проанализировав сразу несколько источников» → **«Выбор авиабилетов из разных источников»**;
- **Черновой заголовок** из первого промпта (до 48 символов) показывается сразу, а когда саммари готово — заменяется; при ошибке API остаётся черновой;
- Заголовок от харнесса (`session/title`) не перебивает наш финальный (он помечается `titleLocked` в state), но принимается, если своего ещё нет;
- **Кэш**: заголовки хранятся в `<home>/dsh-term-state.json` (`titles`), поэтому список открывается мгновенно;
- **`/resume` без аргумента** — интерактивный выбор: **↑/↓ — навигация, Enter — выбрать, Esc — отмена**; набор текста фильтрует список по заголовку/id (Esc при набранном фильтре сначала очищает его). Над списком — линия-разделитель (как у меню команд). Длинные списки показываются окном (12 строк) с пометками «… ещё N».
- **`/resume <что-то>`** строкой принимает: номер в списке, полный id, префикс id или часть заголовка;
- В пайпе/скриптах (не TTY) выбор работает как раньше — нумерованный список и ввод строкой.
- Заголовок виден в строке старта (`resuming session: «…» id`), в `/session` и в списке `/resume`.

Оговорка: сессии, созданные **до** этой фичи, показываются только по id — их логи лежат многофреймовым zstd, а Node умеет читать лишь первый фрейм (там только заголовок сессии). Заголовок появится, как только такая сессия получит новый `session/title` от харнесса.

## Примечания

- **Анимация** — только в интерактивном терминале (TTY); отключить: `DSH_TERM_NO_ANIM=1`. На пайпе поведение обычное, построчное.
- **Сессии на диске**: `sessions/<ns-по-рабочей-папке>/<sessionId>/session.jsonl[.zstd]` (сжатие zstd по умолчанию); `/resume` находит их рекурсивно.
- **Скриптовый ввод**: stdin читается построчно; при EOF (`< file`, Ctrl+Z+Enter) после обработки всех строк CLI корректно завершается. Внимание: пайп из Windows PowerShell 5.1 в нативные процессы не закрывает stdin — для скриптов используйте редирект из файла (`cmd /c "dsh-term < in.txt"`).
- **Внутренности**: реализовано по [@deepseek-ai/dsh-sdk-protocol](C:/Program%20Files/dsh/deepseek-harness/packages/sdk/protocol/README.md): запросы `initialize` / `session/prompt` / `shutdown`; нотификации `session.event` / `session.status` / `subagent.started` / `subagent.finished`; одна JSON-RPC 2.0 фрейма на строку; битые строки игнорируются.
- **Патч харнесса** (resume-сессий): `C:/Program%20Files/dsh/deepseek-harness/packages/sdk/server/` — `createSession` пробует `agents.resume`, а `create` только для новых id. При переустановке харнесса патч сотрётся.
