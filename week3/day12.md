# Day 12 — персонализация поверх модели памяти

Задание: создать профиль пользователя, описать предпочтения (стиль, формат,
ограничения), **подключить профиль к каждому запросу** и проверить, что ассистент
учитывает его автоматически. Результат: персонализированный агент.

Реализация — в `dsh-term` (CLI-клиент харнесса): профиль это долговременная память
о пользователе, которая не лежит в истории диалога, а подаётся в **system prompt
каждого запроса**. Сценарий и данные эксперимента — `week3/day12/`.

## 1. Профиль: файл и формат

```
~/.dsh-term/user-profiles/<slug>.md
```

```markdown
# Профиль пользователя: Только код

## Стиль
- Отвечай кодом, без пояснительного текста.
## Формат
- Один блок кода с языковой пометкой, минимально достаточный для задачи.
## Ограничения
- Не добавляй примеры запуска, если он очевиден из кода.
## Чего избегать
- Markdown-списков, таблиц, заголовков и эмодзи.
```

Формат — обычный markdown, файл правится руками. Секции фиксированы
(`Стиль`, `Формат`, `Ограничения`, `Интересы и контекст`, `Явные просьбы`,
`Чего избегать`) — по ним же профиль собирает LLM, поэтому «описать предпочтения»
не требует ручного оформления: достаточно рассказать, как с вами лучше работать.

## 2. Как профиль подключён к каждому запросу

Профиль уходит оверлеем патча харнесса:

```yaml
- id: system-prompt
  config:
    personaPrefix: |-
      # Профиль пользователя: Только код
      ...
```

То есть профиль становится **префиксом системного промпта** — он есть в каждом
запросе сессии, независимо от стратегии управления контекстом и от того, что уже
вытеснено из окна/сжато компакцией. System prompt фиксируется при спавне рантайма,
поэтому обновление профиля (руками или автоматически) помечает состояние как
«грязное», и перед следующим сообщением `dsh-term` перезапускает рантайм с тем же
`sessionId`: сессия резюмируется, меняется только системный промпт. Это видно в
консоли: `перезапуск рантайма: профиль пользователя обновлён`.

Проверка «профиль реально в промпте» — по диагностике старта
(`profile: «Кратко и по делу» (kratko) · ~276 токенов в system prompt · файл: …`)
и по поведению: правила профиля выполняются, хотя в самом вопросе о них не сказано.

**Приоритет над историей.** Профиль — это то, что пользователь выбрал *сейчас*, но в
переписке могли остаться более ранние договорённости о стиле. Наблюдали живой случай:
профиль «только эмодзи» был подключён и виден в system prompt, а модель отвечала словами,
потому что раньше в той же сессии звучало «эмодзи не нужны» (и модель сама это
подтвердила) — прямое указание в диалоге перевесило системный промпт. Поэтому приоритет
профиля объявлен в двух местах: рамкой в `personaPrefix` и объявлением в **самом свежем
сообщении** (префикс к промпту, как контролы `--format`), которое уходит автоматически при
включении/смене профиля и первым сообщением в продолжаемой сессии. Проверено на сессии с
противоречащей историей: с объявлением — `😊🙂✨`, без него — текст.

## 3. Куда что сохраняется (разделение памяти из day11)

| Тип памяти | Где живёт | Что хранит | Попадает в запрос |
|---|---|---|---|
| Долговременная (профиль) | `~/.dsh-term/user-profiles/<slug>.md` | предпочтения: стиль, формат, ограничения, интересы, просьбы, чего избегать | **всегда** — system prompt (`personaPrefix`) |
| Краткосрочная | транскрипт сессии (харнесс: `sessions/…/session.jsonl`) | реплики текущего диалога | по окну/стратегии контекста |
| Рабочая | `~/.dsh-term/context/<sessionId>.json` | `facts`, ветки, окно режима стратегий (day10) | в запрос хода в режимах `sliding`/`facts`/`branch` |

Три слоя не смешиваются: профиль не дублируется в истории (иначе он бы вытеснялся
окном и сжимался компакцией), а `facts` не подменяют профиль — они про задачу,
профиль про пользователя. Что и куда попало — выбирается явно: пользователь описывает
профиль сам, а автообучение кладёт пункт только в одну из шести секций.

## 4. Автоматическое применение: правила сработали без упоминания

Три профиля × три вопроса, вопросы везде одинаковые и о профиле не упоминают.
Проверка (пороги взяты из текста самих профилей, а не подогнаны):

- `kratko` — «максимум 5 строк обычного текста», без резюме и вступлений;
- `podrobno` — структура (разбор по пунктам) и/или раздел «Итого»;
- `tolko-kod` — либо почти всё код, либо (если текста не избежать) одна строка.

```
kratko      3 из 3 ответов: Q1✔ Q2✔ Q3✔
podrobno    3 из 3 ответов: Q1✔ Q2✔ Q3✔
tolko-kod   3 из 3 ответов: Q1✔ Q2✔ Q3✔
```

Контраст виден сразу. Один и тот же вопрос «Стоит ли заводить отдельную ветку в git
под правку в одну строку?»:

- `kratko` — одна фраза и две строки команд, 216 символов;
- `podrobno` — 5941 символ: заголовок, разбор по пунктам, критерий, компромисс,
  раздел «Итого»;
- `tolko-kod` — блок кода с тремя короткими комментариями и без объяснений
  (385 символов, 97% кода): прозы в ответе нет;
- без персонализации — 1322 символа списочного ответа средней структуры.

## 5. Эксперимент: три профиля на одном наборе вопросов

| Профиль | Ответ, символов | Код, % | in-токены | out-токены | Резюме | Профиль в промпте, токенов | Правила сработали |
|---|---|---|---|---|---|---|---|
| без профиля | 2064 | 24 | 8000 | 970 | 0 из 3 | — | — |
| `kratko` — Кратко и по делу | 332 | 37 | 8367 | 203 | 0 из 3 | 276 | 3 из 3 |
| `podrobno` — Подробно с объяснением | 7015 | 16 | 32967 | 5200 | 3 из 3 | 297 | 3 из 3 |
| `tolko-kod` — Только код | 503 | 97 | 8300 | 250 | 0 из 3 | 259 | 3 из 3 |

(средние по трём вопросам; `in-токены` — сумма по всем запросам хода, `out-токены` —
сгенерированный текст; полный разбор — `node week3/day12/analyze.mjs --md`)

Что видно из данных:

- **Ответы различаются в разы**: 503 символа у `tolko-kod` против 7015 у `podrobno`
  на тех же вопросах. Это эффект профиля, а не температуры: у всех плеч одна модель,
  один промпт вопроса и один прогон без истории.
- **Стиль меняется по всем трём осям** (длина, структура, доля кода): `tolko-kod`
  даёт 97% кода во всех трёх ответах (и ни одной строки прозы), `podrobno` — резюме
  в 3 ответах из 3 и 5–9 заголовков на ответ, `kratko` — ни одного заголовка и ни
  одного списка.
- **Расход при этом падает**: `kratko` — 203 out-токена против 970 у ответа без профиля
  (почти в 5 раз), `tolko-kod` — 250. `podrobno` — 5200 out-токенов: подробность стоит
  денег, и это осознанный выбор профиля.
- **in-токены**: базовая линия 8000 (системный промпт + инструменты + вопрос),
  с профилем ~8300 — профиль занимает **~280 токенов на каждый запрос** (вместе с
  рамкой приоритета; сам текст профиля — 197–217 токенов, см. `/profile list`).
  На длинном диалоге это фиксированная добавка, которая не растёт с историей (в
  отличие от `facts`-обновлений из day10). У `podrobno` средние in-токены выше (32967),
  потому что длинные ответы не укладываются в один запрос: модель делает несколько
  шагов и in-токены суммируются — это свойство длинного ответа, а не профиля.

Оговорка про чистоту сравнения: в интерактивной сессии профиль дообучается по ходу,
поэтому плечи гоняются в one-shot (`-p`), где обучение выключено — все четыре плеча
получают ровно тот профиль, что лежит в `profiles/`, и прогон воспроизводим.

## 6. Обучение профиля по ходу диалога

Кроме ручного описания профиль **дополняется сам**: после каждого сообщения
пользователя (в интерактивной сессии) фоновым вызовом LLM ищется то, что в сообщении
нового о стиле, формате, ограничениях, контексте, просьбах и нелюбимом. Найденное
мержится с дедупликацией (до 6 пунктов на секцию), и профиль уходит в промпт со
следующего хода:

```
· профиль: +3 пункт(ов) (формат: 3, явные просьбы: 1) → в промпт со следующего хода
```

Проверка — `week3/day12/run-learn.ps1` (профиль с одним пунктом → одно сообщение
«запомни про меня: …» → `/exit`), результат в `runs/auto-learn-*.md`:

```
- Отвечай на русском.
+ ## Формат
+ - Не используй эмодзи в ответах.
+ - Метрики всегда указывай в токенах.
+ - В конце длинного ответа добавляй раздел «Итого».
+ ## Явные просьбы
+ - Запомни: эмодзи не нужны, метрики в токенах, в конце длинного ответа — раздел «Итого».
```

Разбор не блокирует ответ модели (запускается сразу после отправки промпта) и не
тратит контекст диалога: это отдельный вызов «профиль + сообщение → JSON с пунктами».

Что здесь честно неидеально: в первой версии промпта разбора LLM разложила одну и ту же
просьбу по трём секциям («Не использовать эмодзи» в стиле, «Избегать эмодзи» в «чего
избегать», плюс мета-пункт «Запомнить предпочтения»). После правки промпта («каждый пункт
ровно в одну секцию — самую точную по смыслу»; запрет мета-пунктов) разбор стал чище, но
дублирование осталось частичным: три правила легли в «Формат», а в «Явные просьбы» попало
их же перечисление одной строкой. Пункты генерирует модель, поэтому профиль стоит
просматривать (`/profile`) и править прямо в файле, а при перерасходе бюджета он
дополнительно сжимается вызовом с явным «убрать повторы».

## 7. UX: как это выглядит для пользователя

```
$ dsh-term --with-profiles
профиль> 
 ▸ • tolko-kod — Только код                   ~180 токенов
     podrobno — Подробно с объяснением         ~217 токенов
     + создать новый профиль                   по вашему описанию

# то же в пайпе (не-TTY) — нумерованный список, выбор номером или id:
  1. t-podrobno — Тест подробно — ~34 токенов
  2. t-kratko — Тест кратко — ~31 токенов
  3. + создать новый профиль — по вашему описанию
номер или id (Enter — отмена): 2
profile: «Тест кратко» (t-kratko) · ~31 токенов в system prompt · файл: …
```

- `--with-profiles` — меню профилей на старте (если профилей нет — сразу предложит
  описать первый: «как с вами лучше работать» → LLM собирает заголовок ≤5 слов и пункты);
- `--user-profile <slug>` (env `DSH_TERM_USER_PROFILE`) — без меню, для скриптов и прогонов;
- в сессии: `/profile` (показать), `/profile list`, `/profile use <slug>`, `/profile new`,
  `/profile off`; смена профиля применяется со следующего сообщения;
- старт печатает `profile: «…» (slug) · ~N токенов в system prompt · файл: …`,
  `/context` — строку `profile:` с расходом на автообучение.

## 8. Итог

- Профиль пользователя — отдельный файл на диске, подключается к **каждому** запросу
  через `personaPrefix` системного промпта, а не через историю диалога.
- Три контрастных профиля на одном наборе вопросов дали разные ответы по стилю, формату
  и объёму кода, а правила профиля выполнялись автоматически — 9 из 9 проверок.
- Профиль можно задать описанием (LLM собирает файл), руками (markdown) и в диалоге
  (автообучение по сообщениям), переключать и отключать без выхода из сессии.
- Профиль приоритетнее истории: если в переписке раньше звучала просьба о стиле,
  включение профиля отменяет её — объявление уходит в первом же сообщении.
- Цена — ~280 токенов в каждом запросе (профиль + рамка приоритета); выигрыш — ответ
  в нужном формате с первого раза и почти в 5 раз меньше output-токенов там, где
  профиль просит краткости.

## 9. Проверки (что и как подтверждено)

| Что | Как проверено | Результат |
|---|---|---|
| профиль действительно в system prompt | строка старта + поведение без упоминания профиля в вопросе | `profile: «…» (slug) · ~276 токенов в system prompt`; 9 из 9 правил |
| обновление подхватывается между ходами | 2 хода в одной сессии, `runs/hot-update-console.txt` | `· профиль: +1 пункт(ов) … → в промпт со следующего хода` → `перезапуск рантайма: профиль пользователя обновлён` перед следующим `queued` |
| профиль главнее прежних договорённостей | сессия, где раньше звучало «эмодзи не нужны», + профиль «только эмодзи» | с объявлением — `😊🙂✨`, без него — текстовый ответ со ссылкой на старые правила |
| бюджет профиля соблюдается | профиль на 878 токенов + новый пункт, `runs/profile-compact-console.txt` | `профиль перерос бюджет ~700 токенов и сжат до ~566`, пунктов — по 6 на секцию |
| автообучение из сообщения | одно сообщение + `/exit`, `runs/auto-learn-*.md` | профиль 135 → 557 байт, три правила в `## Формат` |
| меню профилей на старте | `--with-profiles` в пайпе | нумерованный список, выбор `2` → `profile: «Тест кратко» (t-kratko)` |
| оверлей `personaPrefix` и рамка приоритета | `dsh-term/tests/profile.test.mjs` | 8 из 8 проверок |
