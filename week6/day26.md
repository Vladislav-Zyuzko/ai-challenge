# Day 26 — Запуск локальной LLM

Задание: установить и запустить любую локальную LLM, проверить, что модель запускается локально,
к ней можно обратиться через CLI или HTTP API и она отвечает на простой запрос; сделать минимум
три запроса разной сложности.

Сверх задания (по договорённости): подключить локальную модель к `dsh-term` через команду
`/model` рядом с облачными моделями DeepSeek и научить её ходить в RAG.

## 1. Выбор модели: почему qwen3:8b

Железо определило выбор: **дискретной видеокарты нет** (только встроенная Radeon 780M,
она делит системную память), значит инференс на CPU — Ryzen 7 8845HS, 8 ядер / 16 потоков,
31.3 ГБ RAM, из них свободно ~17.5 ГБ. При RAG в памяти живут ещё эмбеддинг-модель `bge-m3`
(1.2 ГБ) и индексы, поэтому на генеративную модель остаётся ~14–15 ГБ.

| Модель | Размер (реестр Ollama) | Русский | Tool calling | Вердикт |
|---|---|---|---|---|
| **`qwen3:8b`** | **4.9 ГБ** | хороший | **да** | выбрана |
| `qwen3:14b` | 8.6 ГБ | лучше | да | запасной вариант «качество» |
| `gpt-oss:20b` | 12.8 ГБ | средний | да | MoE быстрее, но русский слабее |
| `qwen3:30b-a3b` | 17.3 ГБ | отличный | да | не влезает: 17.3 + 1.2 + Windows ≈ своп |
| `gemma3:12b` | 7.6 ГБ | отличный | **нет** | не подходит: в Ollama у Gemma 3 нет нативного tool calling |
| `mistral-small3.2:24b` | 14.1 ГБ | хороший | да | тесно и медленно |

Решающий аргумент — **tool calling**: наш RAG работает через инструмент `rag_search`, и без
tool calling модель не сможет ходить в базу в живом чате. У qwen3 он поддержан (в официальной
документации Ollama пример tool calling построен именно на `qwen3`), русский язык на приемлемом
уровне, а 4.9 ГБ оставляют большой запас памяти.

Модель поставлена в Ollama (`ollama pull qwen3:8b`), сервер — 0.40.1 с двумя моделями:
`qwen3:8b` (5.2 ГБ) и `bge-m3` для эмбеддингов.

## 2. Проверка: модель отвечает

Проверка оформлена командой проекта, чтобы результат был воспроизводимым:

```powershell
cd doc-index
python -m doc_index.local_check --model qwen3:8b --json out/local-llm.json
```

Что она делает: список моделей из Ollama → три запроса разной сложности через нативный
`/api/chat` → запрос через OpenAI-совместимый `/v1/chat/completions` → проверка tool calling.

| Запрос | Сложность | Время | Токенов | Скорость |
|---|---|---|---|---|
| «Столица Австралии?» | простой факт | 1.2 с | 5 | 4.3 ток/с |
| «Чем RAG отличается от дообучения» | объяснение с планом | 14.1 с | 114 | 8.1 ток/с |
| функция `rrf(rank_lists, k=60)` + пояснение | код и рассуждение | 94.5 с | 768 | 8.1 ток/с |
| «что такое эмбеддинг» через `/v1/chat/completions` | OpenAI-совместимый API | 38.9 с | — | — |
| вызов `rag_search` по запросу | tool calling | 12.6 с | — | — |

Итог проверки: запросов 3/3, в среднем 36.6 с и **8 ток/с**, OpenAI-совместимый API работает,
**tool calling подтверждён** — модель вызвала `rag_search`.

Отдельно стоит знать про режим рассуждений: у qwen3 он включён по умолчанию, и на CPU задача
на код в нём не уложилась даже в 5 минут. В проверке рассуждения выключены (`think: false`) —
иначе один запрос занимает минуты; при этом качество кода остаётся достаточным.

## 3. Подключение к dsh-term: модель в списке `/model`

Локальная модель подключается **маршрутом pi-ai**, который объявляется документом настроек
`$DSH_HOME/settings.yaml`:

```yaml
llm-pi-ai:
  providers:
    local:
      displayName: Локальная модель (Ollama)
      api: openai-completions
      baseURL: http://127.0.0.1:11434/v1
      apiKeyEnv: OLLAMA_API_KEY
      models:
        - id: 'qwen3:8b'
          name: 'qwen3:8b (локально)'
          contextWindow: 32768
          maxTokens: 4096
```

Три вещи, которые выяснились по ходу и определили решение:

1. **Патчем маршрут не добавить.** Первая попытка вставить адаптер `dsh-llm-pi-ai` вторым
   экземпляром упала с «provider is already declared»: адаптер уже смонтирован «спящим»
   (ноль маршрутов), и его маршруты подаются именно секцией настроек. Это штатный путь —
   им пользуется веб-страница моделей, — и он же позволяет править маршрут без перезапуска.
2. **`contextWindow` задаём явно.** У qwen3 в Ollama по умолчанию 4096 токенов, а RAG кладёт
   в промпт несколько тысяч токенов контекста плюс схемы инструментов — с дефолтом контекст
   молча обрезался бы.
3. **Ключ нужен, хотя Ollama его не проверяет**: маршрут pi-ai падает с `MISSING_CREDENTIAL`,
   если `apiKeyEnv` ни на что не ссылается. dsh-term подставляет фиктивное значение в env.

Команда `/model` показывает список и переключает модель:

```
dsh> /model show
модель: deepseek-v4-flash · провайдер deepseek-official
  ● DeepSeek-V4-Flash · облако DeepSeek
  ○ DeepSeek-V4-Pro · облако DeepSeek
  ○ DeepSeek-V41-Flash · облако DeepSeek
  ○ DeepSeek-V4-Flash-Vision-Exp · облако DeepSeek
  ○ qwen3:8b · локально (Ollama)
  всего 5 · локальных 1
dsh> /model qwen3:8b
модель: qwen3:8b · локально (Ollama)
  перезапуск рантайма: смена модели на qwen3:8b
```

Выбор сохраняется в состоянии dsh-term и держится между запусками; `/model` без аргумента
открывает меню, `--provider local --model qwen3:8b` работает как флаг запуска. Диагностика
`--llm-check` показывает, что именно записано в конфиг, и какие модели видит Ollama.

## 4. Локальная модель и RAG

Здесь результат разный для двух путей, и это главный вывод дня.

**Строгий путь — работает.** Строгая функция RAG (день 24: контракт `ОТВЕТ` + `ИСТОЧНИКИ` +
`ЦИТАТЫ`, проверка дословности, отказ по порогу) не требует агентского цикла: контекст
вкладывается в промпт. Локальная модель отвечает по нему так же, как облачная:

```powershell
python -m doc_index brief "Что такое MCP и какую задачу решает?" --backend local --llm-model qwen3:8b
```

Результат прогона:

```
## ИСТОЧНИКИ
- [1] structural:ai-gladkov/20_Знания_1/4_01_Что_такое_MCP.md#0001 — ai-gladkov › Знания 1 › 4.01–4.14
- [2] ...#0007    - [3] ...#0004
## ЦИТАТЫ
- [1] «MCP (Model Context Protocol) — специальный протокол (разработан Anthropic)…»
- [2] «Задача MCP — взять различия между API и различия между нейронками…»
- [3] «MCP — это стандарт, а не готовый фреймворк…»

**Проверка:** источники 3/3 реальны · цитаты 3/3 дословны · выдуманных 0 · фрагментов 3 · лучшее совпадение 0.660
```

В dsh-term это доступно как `/rag-brief`: если сессия переключена на локальную модель,
справка считается ею же.

**Агентский цикл — не работает на 8B.** В живом чате с включённым RAG (`--rag`) qwen3:8b
не выбирает нужный инструмент: в промпте у агента больше двадцати инструментов харнесса
(файлы, shell, веб-поиск, цели), и модель уходит в сторону — в прогоне она начала рассуждать
про права доступа к файлам вместо поиска по базе. Это не дефект интеграции, а ограничение
модели: инструментов слишком много, и 8B не держит выбор. Варианты решения — модель крупнее
(14B) или урезанный набор инструментов для локального профиля; для строгого пути ни то, ни
другое не нужно.

## 5. Что нашли по ходу

**Пакет `mcp` в окружении сменился с 2.2.0 на 1.30.0** — и MCP-сервер RAG перестал
запускаться («No module named 'mcp.server.mcpserver'»), из-за чего агент молча остался без
инструмента. В ветке 2.x класс называется `MCPServer`, в 1.x — `FastMCP`; теперь сервер
поддерживает обе ветки, а в стартовую диагностику добавлена строка с интерпретатором:

```
rag: python C:\...\Python312\python.exe · 3.12.10
```

Это тот же класс ошибок, что и в дне 25: сервер инструментов падает — агент не жалуется,
а просто отвечает хуже. Диагностика теперь показывает, кто запущен.

## 6. Ограничения

- **Один прогон на модель.** Скорости (8 ток/с) измерены на этом CPU при работающих
  приложениях; на пустой системе будет немного выше.
- **Режим рассуждений выключен** в проверке, иначе запросы занимают минуты; качество
  рассуждений с ним выше, но для интерактивной работы на CPU это непрактично.
- **iGPU не задействован.** Ollama умеет использовать Radeon 780M через Vulkan, но по этой
  связке на Windows есть известные просадки производительности; сравнение с CPU не проводилось.
- **Агентский путь с локальной моделью не решён** — нужен либо крупнее модель, либо
  урезанный набор инструментов (см. §4).
- **Маршрут локальной модели привязан к адресу Ollama** (`DSH_TERM_OLLAMA`, по умолчанию
  `http://127.0.0.1:11434`); при смене адреса секция настроек перезаписывается при старте.

## 7. Итог

1. **Локальная LLM запущена и отвечает**: `qwen3:8b` в Ollama 0.40.1, 8 ток/с на CPU,
   три запроса разной сложности пройдены (факт 1.2 с, объяснение 14.1 с, код 94.5 с).
2. **Доступ есть и через CLI, и через HTTP** — нативный `/api/chat` и OpenAI-совместимый
   `/v1/chat/completions`; последний и есть тот протокол, по которому харнесс общается с моделью.
3. **Tool calling работает** — модель вызвала `rag_search`, то есть технически готова к RAG.
4. **В dsh-term добавлена команда `/model`**: четыре облачные модели DeepSeek и локальная
   в одном списке, выбор сохраняется между запусками, переключение — перезапуск рантайма.
5. **Локальная модель отвечает по RAG через строгий путь**: 3 источника из 3, 3 дословные
   цитаты из 3, выдуманных 0 — то есть локальная модель даёт ответы с источниками без облака.
6. **В агентском цикле 8B теряется** среди двадцати с лишним инструментов: для локального
   агента нужна модель крупнее или сокращённый набор инструментов.
7. **Побочно найден и починен дефект:** смена версии пакета `mcp` (2.2.0 → 1.30.0) ломала
   MCP-сервер RAG; теперь сервер работает с обеими ветками SDK.
