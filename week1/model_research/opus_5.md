# 2D Fenwick Tree — Range Sum with Point Updates (Dart)

**Модель:** Opus 5. **Задача:** `week1/model_research/input.md` — класс `Fenwick2D` с точечным обновлением и суммой по прямоугольнику.

## Идея решения

Дерево Фенвика (BIT) хранит частичные суммы так, что и обновление, и префиксный запрос стоят `O(log n)`. Двумерный вариант — это дерево Фенвика по строкам, каждый узел которого сам является деревом Фенвика по столбцам.

Три опорных момента:

1. **Внутренние индексы 1-based.** Логика `i & -i` (младший установленный бит) требует ненулевых индексов, поэтому внутри дерево нумеруется с 1, а публичный API остаётся 0-based, как в условии.
2. **Обновление через дельту.** BIT умеет прибавлять, а не присваивать. Чтобы `update` заменял значение, класс держит копию текущей матрицы `_values` и прибавляет разницу `newValue - _values[row][col]`.
3. **Сумма прямоугольника через включение-исключение.** Для прямоугольника `(r1,c1)..(r2,c2)` берём четыре префиксные суммы: `P(r2,c2) - P(r1-1,c2) - P(r2,c1-1) + P(r1-1,c1-1)`.

Отдельно стоит построение. Наивный вариант — `M*N` вызовов `update` за `O(M·N·log M·log N)`. Здесь используется линейное построение за `O(M·N)`: сначала по каждой строке значения проталкиваются к «родителю» по столбцам, затем готовые строки проталкиваются к родителю по строкам. Два прохода нельзя объединить в один цикл: если строка-родитель уже накопила вклад предыдущих строк, внутристрочное проталкивание продублирует его.

## Решение

```dart
/// Двумерное дерево Фенвика: точечное присваивание и сумма по прямоугольнику.
///
/// Публичный API 0-based, внутреннее дерево 1-based.
/// Построение: O(M*N). update: O(log M * log N). query: O(log M * log N).
/// Память: O(M*N).
class Fenwick2D {
  final int _rows;
  final int _cols;

  /// Актуальные значения матрицы — нужны, чтобы update умел присваивать,
  /// а не только прибавлять.
  final List<List<int>> _values;

  /// Дерево частичных сумм, индексы 1..rows / 1..cols.
  final List<List<int>> _tree;

  Fenwick2D(List<List<int>> matrix)
      : _rows = matrix.length,
        _cols = matrix.isEmpty ? 0 : matrix.first.length,
        _values = [for (final row in matrix) List<int>.of(row)],
        _tree = List.generate(
          matrix.length + 1,
          (_) => List<int>.filled(
            (matrix.isEmpty ? 0 : matrix.first.length) + 1,
            0,
          ),
          growable: false,
        ) {
    for (final row in matrix) {
      if (row.length != _cols) {
        throw ArgumentError('Матрица должна быть прямоугольной');
      }
    }
    _build();
  }

  int get rows => _rows;
  int get cols => _cols;

  /// Заменяет значение в ячейке (row, col) на newValue.
  void update(int row, int col, int newValue) {
    _checkCell(row, col);
    final delta = newValue - _values[row][col];
    if (delta == 0) return;
    _values[row][col] = newValue;

    for (var i = row + 1; i <= _rows; i += i & -i) {
      final treeRow = _tree[i];
      for (var j = col + 1; j <= _cols; j += j & -j) {
        treeRow[j] += delta;
      }
    }
  }

  /// Сумма элементов прямоугольника (row1, col1)..(row2, col2) включительно.
  int query(int row1, int col1, int row2, int col2) {
    _checkCell(row1, col1);
    _checkCell(row2, col2);
    if (row1 > row2 || col1 > col2) {
      throw RangeError('Ожидается row1 <= row2 и col1 <= col2');
    }

    return _prefix(row2 + 1, col2 + 1) -
        _prefix(row1, col2 + 1) -
        _prefix(row2 + 1, col1) +
        _prefix(row1, col1);
  }

  /// Текущее значение ячейки — удобно для отладки и тестов.
  int valueAt(int row, int col) {
    _checkCell(row, col);
    return _values[row][col];
  }

  /// Линейное построение: сначала по столбцам внутри каждой строки,
  /// затем по строкам. Порядок проходов важен, объединять их нельзя.
  void _build() {
    for (var i = 1; i <= _rows; i++) {
      final treeRow = _tree[i];
      final sourceRow = _values[i - 1];
      for (var j = 1; j <= _cols; j++) {
        treeRow[j] += sourceRow[j - 1];
        final parent = j + (j & -j);
        if (parent <= _cols) treeRow[parent] += treeRow[j];
      }
    }

    for (var i = 1; i <= _rows; i++) {
      final parent = i + (i & -i);
      if (parent > _rows) continue;
      final from = _tree[i];
      final to = _tree[parent];
      for (var j = 1; j <= _cols; j++) {
        to[j] += from[j];
      }
    }
  }

  /// Сумма подматрицы [0..r) x [0..c) в 1-based координатах дерева.
  int _prefix(int r, int c) {
    var sum = 0;
    for (var i = r; i > 0; i -= i & -i) {
      final treeRow = _tree[i];
      for (var j = c; j > 0; j -= j & -j) {
        sum += treeRow[j];
      }
    }
    return sum;
  }

  void _checkCell(int row, int col) {
    if (row < 0 || row >= _rows) {
      throw RangeError.index(row, _values, 'row', 'Строка вне диапазона');
    }
    if (col < 0 || col >= _cols) {
      throw RangeError.index(col, _values.first, 'col', 'Столбец вне диапазона');
    }
  }
}
```

## Пример из условия

```dart
void main() {
  final matrix = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9],
  ];

  final fw = Fenwick2D(matrix);
  print(fw.query(0, 0, 2, 2)); // 45

  fw.update(1, 1, 10);
  print(fw.query(0, 0, 2, 2)); // 50

  print(fw.query(0, 1, 2, 2)); // 35
}
```

Первые два запроса совпадают с условием. Третий требует оговорки.

Прямоугольник `query(0, 1, 2, 2)` — это строки 0..2 и столбцы 1..2, то есть шесть ячеек после обновления: `2 + 3 + 10 + 6 + 8 + 9 = 38`. Проверка с другой стороны: сумма всей матрицы равна 50, первый столбец даёт `1 + 4 + 7 = 12`, остаток `50 - 12 = 38`.

В условии для этого запроса указано 35, а в комментарии перечислены только пять слагаемых: пропущен элемент `matrix[0][2] = 3`. Это опечатка в постановке задачи, а не расхождение алгоритма. Код возвращает **38**.

## Сложность

| Операция | Время | Память |
|---|---|---|
| Конструктор | `O(M·N)` | `O(M·N)` |
| `update` | `O(log M · log N)` | — |
| `query` | `O(log M · log N)` | — |

Четыре префиксных вызова в `query` дают константный множитель 4, он не меняет асимптотику.

## Крайние случаи, которые покрыты кодом

- **Матрица 1×1.** Единственный запрос `query(0,0,0,0)` возвращает значение ячейки, циклы дерева отрабатывают по одному шагу.
- **Пустая матрица.** `Fenwick2D([])` не падает в конструкторе: `_cols` вычисляется как 0. Любой вызов `update` или `query` даст `RangeError`, что корректно, так как валидных индексов нет.
- **Неровные строки.** Конструктор бросает `ArgumentError`, вместо того чтобы молча считать неверные суммы.
- **Обновление тем же значением.** `delta == 0`, метод выходит сразу и не трогает дерево.
- **Отрицательные значения и нули.** Дерево Фенвика работает с любой аддитивной группой, знак значения роли не играет.
- **Вырожденный прямоугольник.** Запрос одной строки или одного столбца обрабатывается общей формулой, отдельная ветка не нужна.
- **Переполнение.** На Dart VM `int` 64-битный, суммы до `9.2·10^18` безопасны. При компиляции в JavaScript `int` становится числом с плавающей точкой, и точность теряется после `2^53`. Для веба нужен `BigInt` или гарантия малых сумм.

## Замечания по API

Конструктор копирует входную матрицу через `List<int>.of`, поэтому внешние изменения `matrix` после создания объекта не рассинхронизируют дерево. Это стоит `O(M·N)` памяти сверх самого дерева, но избавляет от целого класса ошибок совместного владения данными.

Метод `valueAt` добавлен сверх условия. Он бесплатен, так как значения и так хранятся, и превращает отладку в чтение одной ячейки вместо запроса `query(r, c, r, c)`.
