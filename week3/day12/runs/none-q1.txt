# Чтение JSON-файла в Node.js с обработкой ошибок

## 1. Синхронно (просто и предсказуемо)

```js
const fs = require('node:fs');

function readJsonSync(path) {
  let raw;
  try {
    raw = fs.readFileSync(path, 'utf8');
  } catch (err) {
    // Ошибки файловой системы
    if (err.code === 'ENOENT') throw new Error(`Файл не найден: ${path}`);
    if (err.code === 'EACCES') throw new Error(`Нет прав на чтение: ${path}`);
    if (err.code === 'EISDIR') throw new Error(`Это каталог, а не файл: ${path}`);
    throw err; // всё остальное не глотаем
  }

  try {
    return JSON.parse(raw);
  } catch (err) {
    // Ошибки парсинга — это SyntaxError
    throw new Error(`Некорректный JSON в ${path}: ${err.message}`, { cause: err });
  }
}
```

Ключевое: **это две разные категории ошибок**, и обрабатывать их нужно раздельно.
- Ошибки чтения — объект `Error` с полем `err.code` (`ENOENT`, `EACCES`, `EISDIR`, `EMFILE`…).
- Ошибки разбора — `SyntaxError` из `JSON.parse`, у него **нет** `err.code`, зато есть `err.message` с позицией (в современных версиях Node — `line/column`).

## 2. Асинхронно через `fs/promises` (предпочтительно)

```js
const fs = require('node:fs/promises');

async function readJson(path) {
  try {
    const raw = await fs.readFile(path, 'utf8');
    return JSON.parse(raw);
  } catch (err) {
    if (err instanceof SyntaxError) {
      throw new Error(`Некорректный JSON в ${path}: ${err.message}`, { cause: err });
    }
    if (err.code === 'ENOENT') return null; // например, дефолт вместо ошибки
    throw err;
  }
}
```

Важно: `JSON.parse` бросает **синхронно**, поэтому `await` его не спасает — `try/catch` вокруг всей функции обязателен, либо `JSON.parse` нужно оборачивать отдельно.

## 3. Через callback

```js
const fs = require('node:fs');

fs.readFile('config.json', 'utf8', (err, raw) => {
  if (err) return console.error('Ошибка чтения:', err.code, err.message);
  try {
    const data = JSON.parse(raw);
    console.log(data);
  } catch (e) {
    console.error('Ошибка парсинга:', e.message);
  }
});
```

## 4. `require()` — только для статических конфигов

```js
const config = require('./config.json'); // кэшируется, синхронно, падает при битом JSON
```

Ошибка тоже `SyntaxError`, но перехватить её локально сложно, а результат кэшируется навсегда. Для рантайм-данных, которые меняются, не подходит.

## 5. ESM (Node 22+)

```js
import config from './config.json' with { type: 'json' };
```

Устаревший вариант — `assert { type: 'json' }`; не используйте его в новом коде.

## 6. Типичные подводные камни

| Проблема | Симптом | Решение |
|---|---|---|
| BOM в начале файла | `SyntaxError: Unexpected token` | `raw.replace(/^\uFEFF/, '')` |
| Пустой файл | `Unexpected end of JSON input` | Проверить `raw.trim() === ''` |
| Файл меняется во время чтения | Частичный/битый JSON | Атомарная запись (`write-file-atomic`) или чтение+валидация |
| Огромный файл | Высокое потребление памяти | Потоковый парсер `stream-json` / `JSONStream` |
| Нет `err.code` у `SyntaxError` | Ветка обработки не срабатывает | Проверять `err instanceof SyntaxError`, а не `err.code` |

## 7. Полный безопасный вариант

```js
const fs = require('node:fs/promises');

async function loadJson(path, { required = true } = {}) {
  let raw;
  try {
    raw = await fs.readFile(path, 'utf8');
  } catch (err) {
    if (!required && err.code === 'ENOENT') return null;
    throw new Error(`Не удалось прочитать ${path}: ${err.message}`, { cause: err });
  }

  try {
    return JSON.parse(raw.replace(/^\uFEFF/, ''));
  } catch (err) {
    throw new Error(`Невалидный JSON в ${path}: ${err.message}`, { cause: err });
  }
}

// использование
const cfg = await loadJson('./config.json').catch(err => {
  console.error(err.message, { cause: err.cause });
  process.exitCode = 1;
});
```

**Короткий ответ:** `await fs.readFile(path, 'utf8')` + `JSON.parse` внутри `try/catch`; ошибки ФС различайте по `err.code`, ошибки формата — по `err instanceof SyntaxError`; не глотайте неизвестные ошибки и сохраняйте исходную через `cause`.
