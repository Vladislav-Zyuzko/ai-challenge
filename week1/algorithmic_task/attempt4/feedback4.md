# Финальное решение (техлид-резюме)

**Файл:** `solution.dart` (в рабочей директории). Итог синтеза фидбеков analyst + engineer + critic:

## Решение

```dart
import 'dart:math';

String minWindow(String s, String t) {
  final List<int> tcp = t.runes.toList();
  if (tcp.isEmpty) return '';
  final List<int> scp = s.runes.toList();
  if (scp.length < tcp.length) return '';

  final Map<int, int> need = <int, int>{};
  for (final int c in tcp) {
    need[c] = (need[c] ?? 0) + 1;
  }

  final Map<int, int> have = <int, int>{};
  int formed = 0; // сколько различных символов t уже «покрыто» окном
  int bestL = 0;
  int bestR = 0;
  int bestLen = scp.length + 1; // «бесконечность»
  int left = 0;

  for (int right = 0; right < scp.length; right++) {
    final int c = scp[right];
    final int? req = need[c];
    if (req != null) {
      final int after = (have[c] ?? 0) + 1;
      have[c] = after;
      if (after == req) formed++; // только в момент достижения кратности
    }

    // Окно валидно: сжимаем слева до упора, фиксируя каждого кандидата.
    while (formed == need.length) {
      final int len = right - left + 1;
      if (len < bestLen) {
        bestLen = len;
        bestL = left;
        bestR = right + 1; // правый конец — исключительный
      }
      final int lc = scp[left];
      final int? lreq = need[lc];
      if (lreq != null) {
        final int after = have[lc]! - 1;
        have[lc] = after;
        if (after < lreq) formed--; // кратность сломана — окно невалидно
      }
      left++;
    }
  }

  if (bestLen > scp.length) return '';
  return String.fromCharCodes(scp.sublist(bestL, bestR));
}
```

## Как фидбеки экспертов сошлись в этом коде

| Требование (из фидбеков) | Как закрыто |
|---|---|
| Скользящее окно O(\|s\|+\|t\|), два указателя (Analyst §4, Engineer §1, Critic §3) | `right` идёт вперёд, `left` суммарно ≤ \|s\| шагов; никаких пересчётов окна |
| Учёт **кратности** через корректный счётчик переходов (Analyst §5, Engineer §1, Critic §1) | `formed` — число *различных* символов `t` с `have ≥ need`; инкремент только при переходе «меньше → достаточно», декремент — при обратном; лишние копии не влияют |
| Не хранить срезы в цикле (Analyst §6.1, Engineer §3, Critic §5) | Хранятся `bestL/bestR`, один `substring`-эквивалент в конце |
| Единая и безопасная единица «символа» (Engineer §5.1, Critic §4) | Единица — **кодовая точка (rune)**: счёт и нарезка в одних единицах, суррогатные пары не разрезаются, сравнение точное (без нормализации/регистра) |
| Конвенции для неоднозначных входов (Analyst §2, Critic §2) | пустая `t` → `""`; \|t\| > \|s\| → `""`; отсутствующий символ → `""` (алгоритм сам, без флага) |
| Точная сигнатура `String minWindow(String s, String t)` | Соблюдена; функция чистая, без побочных эффектов |
| Обновление ответа только на валидных окнах после сжатия (Engineer §5.6) | Запись кандидата до удаления левого символа; обновление строго при меньшей длине (при равенстве допустима любая) |

## Верификация (в `main()` файла, всё зелёное)

- **3 примера из условия:** `(ADOBECODEBANC, ABC)→BANC`, `(a,a)→a`, `(a,aa)→""`.
- **24 краевых теста** из чек-листов экспертов: пустые входы, `t` длиннее `s`, отсутствующий символ, регистр (`a`,`A`→`""`), дубликаты (`aaab,aa→aa`), ответ у краёв (`bba,ab→ba`), мусор вокруг, первое валидное окно не минимально (`ABAACBAB,ABC`), двойная `A`, `s==t`, окно = весь `s`, не-BMP (`😀😀,😀→😀`), не-ASCII BMP (`éa,é→é`).
- **4000 рандомизированных сверок с наивным перебором** (все пары границ + частотные карты): 2000 на ASCII, 2000 на алфавите с эмодзи/`é` — все совпали.
- **Производительность:** `|s|=10⁶` → ~69 мс (найденное окно 34 симв.), ветка «нет решения» — полный проход без квадратичных хвостов; ранний выход `|t|>|s|` — 35 мс.

`dart analyze` в этой песочнице не запускается (среда блокирует дочерний процесс анализатора — access denied), но `dart run` компилирует и исполняет файл без ошибок, а код null-safe (null-проверки `?? 0`, `!` только при гарантированном наличии ключа в окне).

Единственное задокументированное допущение-компромисс: список код-точек стоит O(\|s\|) дополнительной памяти (время остаётся линейным); для ASCII-джаджей это несущественно, зато поведение корректно для произвольного Unicode — что и требовал критик в пункте «треугольник приёмки».
