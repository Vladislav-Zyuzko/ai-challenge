# Задание: управление контекстом (компрессия истории)

Реализовать механизм управления контекстом:

- хранить последние N сообщений «как есть»;
- остальное заменять summary (например, каждые 10 сообщений);
- хранить summary отдельно и подставлять его в запрос вместо полной истории.

Сравнить:

- качество ответов без сжатия;
- качество ответов со сжатием;
- расход токенов до/после.

Результат: агент, который работает с компрессией истории и экономит токены.

## Как это реализовано в dsh-term

Механизм живёт в рантайме DeepSeek Harness (плагин `compaction-basic`), а dsh-term
управляет им и показывает результат:

| Требование | Механизм |
|---|---|
| «последние N сообщений как есть» | `retainTokens` (аналог N сообщений в токенах) |
| «остальное — summary» | авто-компакция при заполнении окна на `thresholdRatio` |
| «summary хранить отдельно и подставлять» | событие `compaction/summary` + подстановка вместо shadowed-диапазона |
| «расход до/после» | сводка dsh-term: `tokens: in (cache …) / out`, `requests`, `context %`, `compression` |

Настройки передаются харнессу патч-оверлеем (`dsh --patch`), который dsh-term
генерирует сам — правки в Program Files не нужны:

```
dsh-term --compress off                 # baseline: компрессия и прунер выключены
dsh-term --compress on                  # по умолчанию: thresholdRatio 0.1, retainTokens 50000
dsh-term --compress 0.01 --compress-keep 2000   # агрессивный режим для эксперимента
/context                                # состояние: настройки, метрики, последний summary
```

## Методика сравнения (A/B)

Один и тот же сценарий диалога (`turns.txt`, 8 ходов) прогоняется дважды в
отдельных чистых home:

- **baseline** — `--compress off`;
- **compress** — `--compress 0.009 --compress-keep 300` (порог 9k токенов, «как есть» — последние 300 токенов).

В начале диалога вводится «иголка» — код проекта `KX-42`; в конце задаются
контрольные вопросы (код, число тем, что было пятым) — так проверяется, не теряет
ли компрессия важную информацию. Ходы специально крупные (по 300 слов), иначе
история растёт медленнее порога и компакции нечего сжимать.

Сравниваются: суммарные `in` / `out` / `cache`, число запросов, финальный размер
контекста, число компакций и их стоимость (вызовы суммаризатора), а также
правильность контрольных ответов.
