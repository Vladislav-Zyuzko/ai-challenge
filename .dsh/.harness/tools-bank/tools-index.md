# Карта инструментов

harness_version: 0.1
Обновлено: 2026-09-20

Карта того, какие внешние инструменты описаны в банке и где лежат их правила.
Узлы продукта ссылаются на эти файлы в своих `tools-rules.md` и добавляют только
заметки, актуальные для своего контекста.

| Инструмент | Для чего уместен | Правила | Статус |
|---|---|---|---|
| web (vanilla HTML+CSS+JS) | Локальный браузерный инструмент без сборки и зависимостей: разметка, оформление, логика интерфейса | `web-rules.md` | active (0.2) |
| node (встроенный тест-раннер) | Автотесты чистой логики на `node:test` и статические проверки файлов (`node:fs`) без установки пакетов | `node-rules.md` | active (0.2) |
| python (статический сервер) | Раздача статики на `127.0.0.1` для ручной проверки в браузере | `python-rules.md` | active (0.1) |

## Как пополняется банк

1. Инструмент появляется тогда, когда он выведен из инвариантов продукта, а не «на всякий случай».
2. Правила пишутся по требованиям `README.md` этого каталога: назначение, предусловия
   с health-check, постановка задачи, проверка результата, практики и грабли, ограничения,
   версия и статус.
3. Предусловия проверяются **командой**, а факт проверки с датой и версиями попадает
   в файл правил — иначе инструмент считается недоступным.
4. Файл правил — единственный писатель; изменения копятся версиями, история не переписывается.

## Исполнители

Инструмент без правил и предусловий недоступен; исполнитель получает эти правила
как системный промпт и одну задачу (рецепт + проверка) — см. `README.md`, раздел
про `<tool>-executor.md`. Отдельные файлы исполнителей создаются, когда узел начинает
делегировать задачи этому инструменту; до этого правила инструмента полностью
описывают, как ставить и проверять задачу.
